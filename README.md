# 砍价 · 到店消费询价 Demo

> 上传一张报价截图，剩下的交给助理去问。

个人在订酒店、订 KTV 包厢、约按摩的时候，常常能看到一个公开报价，却要自己找电话、重复说明需求、反复问有没有优惠——一趟下来十几分钟，还不一定谈得下来。

这个 Demo 想证明的不是「AI 说话像不像真人」，而是：**用户不用重复查找、重复说明，几步就能拿到一个说得清的结果。**

## 品类

一个引擎跑 **6 个品类**，每个品类有自己的字段、计价单位、可谈权益和话术。

| 大类 | 品类 | 询价单位 |
| --- | --- | --- |
| 酒店民宿 | 酒店 / 民宿 | 1 间夜 |
| 休闲娱乐 | KTV | 4 小时（包间） |
| | 按摩足疗 | 2 人次 |
| | 酒吧 | 1 卡座 |
| | 健身房 | 12 次（卡种） |
| | 洗浴桑拿 | 2 人次 |

医美暂不接入：医疗广告不能承诺疗效、不能打「最低价」，平台代客议价医疗项目本身也有争议。

## 三条设计原则

**1. 品类要多，细节必须真。**

不是「9 个品类共用一套字段」，而是「一套渲染逻辑 + 9 份品类配置」。KTV 问的是包型/时段/最低消费/能否自带酒水，酒吧问的是卡座/低消/入场费/开瓶费，健身房问的是卡种/有效期/能否转卡。换成「名称+价格+时段+权益」这种通用字段，第一眼就假。

**2. 只有店名和询价单位必填。**

其余字段全部可选：可以改、可以删、可以自己加。截图里没有的东西，助理不会替你猜，会当场去问。

**3. 价格只显示消费总价。**

不搞「每晚价 / 全程总价」的切换——用户要的就是「这一单多少钱」。询价单位作为分母挂在后面（`¥1,480 / 4 小时`），信息不丢，认知成本最低。

识别出价格后，助理会给一个**议价目标区间**（暂定规则：按标价低 15% 估算），让用户心里有个数。结果页谈到的价格就落在这个区间里——谈到了下限显示「已取得优惠」，没谈下来就如实报原价。

## 六步流程

| 步骤 | 做什么 |
| --- | --- |
| ① 首页 | 按品类渲染：上传框文案、标准截图要素、示例图都跟着品类变 |
| ② 确认询价单 | 识别字段逐项可改；店名与单位必填，其余可删可加；价格只记总价，并给出议价目标区间 |
| ③ 确认需求 | 门店与单位锁定；勾选要谈的权益；填写姓名和手机号后才能开始 |
| ④ 沟通进度 | 五步实时推进，可展开查看双方对话，也可以中途离开 |
| ⑤ 结果卡 | 三种结局都给明确答复 |
| ⑥ 下一步 | 返回记录 / 调整需求再问 / 再次尝试联系 / 查看沟通记录 / 分享 |

---

## 三种结局

| 结局 | 页面给什么 | 下一步 |
| --- | --- | --- |
| **议价成功** | 商家报价、权益、使用规则、与原报价的差异 | 返回、查看沟通记录、分享给好友 |
| **商家无优惠** | 当前报价、商家原话、**额外拿到的权益单独列出** | 调整需求重新询价、查看沟通记录 |
| **未接通** | 明确「未取得报价」，只给联系情况与未确认事项，**不推测任何价格** | 再次尝试联系、查看沟通记录 |

未接通态是整个 Demo 里最较真的地方：绝大多数演示会在这里编一个价格，但真实场景中用户最痛的就是「不知道到底问没问」。

## 几个工程决定

**询价是异步任务，不是一段动画。**
进度页有「等会来看」和「有结果了通知我」两个出口；离开后记录里显示「正在沟通中」，完成后翻成结果。选「通知我」会先让你挑通知方式（短信 / 微信服务通知 / 应用内），默认短信；选「仅应用内提醒」时不会弹通知条。

**进度按真实时间轴推进。**
议价成功与无优惠约 56 秒，未接通约 26 秒。进度由 `Date.now() - startedAt` 驱动，所以可以随时中断、刷新恢复、从记录页点回去继续看。

**记录会持久化。**
用 `localStorage` 存询价记录，跨品类混排，卡片带品类标签。刷新后历史还在；没跑完的询价按剩余时间继续跑完。

## 文件结构

```
index.html   页面骨架
app.css      样式（含小屏适配：窄于 460px 时去掉手机外框，铺满全屏）
app.js       品类配置 + 渲染引擎
samples/     酒店示例截图
```

加一个新品类的成本：在 `app.js` 的 `CATS` 里加约 30 行配置（单位、字段、可谈权益、话术、三种结局文案），列表页自动出现，不用动渲染逻辑。

## 说明

- 所有商家、电话、通话内容、价格均为**演示数据**，页面不会发出任何网络请求
- 不拨真实电话，不出现订单号、支付成功、订房成功
- 姓名和手机号只用于本次询价的界面展示，不上传
- 结果卡固定注明「信息仅供参考，需以商家最终确认和实际预订为准」

这是一个产品原型，用于讨论产品形态，不是可用的商业服务。
