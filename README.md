# 砍价 · 酒店询价 Demo

> 上传一张酒店报价截图，剩下的交给助理去问。

个人用户订酒店时，常常能看到一个公开报价，却要自己找电话、重复说明需求、反复问有没有优惠——一趟下来十几分钟，还不一定谈得下来。

这个 Demo 想证明的不是「AI 说话像不像真人」，而是：**用户不用重复查找、重复说明，几步就能拿到一个说得清的结果。**

## 六步流程

| 步骤 | 做什么 |
| --- | --- |
| ① 主页 | 上传酒店报价截图（真实文件选择器），页面明确列出「标准截图需要包含」的四要素 |
| ② 确认询价单 | 识别结果逐项可改；价格区分「每晚价 / 全程总价」；截图中缺失的信息标出来让你补，不替你猜 |
| ③ 确认需求 | 房型来自截图、不可修改；勾选需要的权益；**填写姓名和手机号**后才能开始询价 |
| ④ 沟通进度 | 五步实时推进，可展开查看双方对话，也可以中途离开 |
| ⑤ 结果卡 | 三种结局都给明确答复 |
| ⑥ 下一步 | 返回记录 / 调整需求再问 / 再次尝试联系 / 查看沟通记录 / 分享 |

---

## 三种结局，三种下一步

| 结局 | 页面给什么 | 下一步 |
| --- | --- | --- |
| **议价成功** | 商家报价、房型权益、取消条件、与原报价的差异 | 返回、查看沟通记录、分享给好友 |
| **商家无优惠** | 当前报价、商家原话、**额外拿到的权益单独列出** | 调整需求重新询价、查看沟通记录 |
| **未接通** | 明确「未取得报价」，只给联系情况与未确认事项，**不推测任何价格** | 再次尝试联系（同需求直接重发）、查看沟通记录 |

未接通态是整个 Demo 里最较真的地方：绝大多数演示会在这里编一个价格，但真实场景中用户最痛的就是「不知道到底问没问」。

## 几个产品决定

**询价是异步任务，不是一段动画。**
进度页有「等会来看」和「有结果了通知我」两个出口；离开后记录里显示「正在沟通中」，完成后翻成结果。选「通知我」会先让你挑通知方式（短信 / 微信服务通知 / 应用内），默认短信。

**进度按真实时间轴推进。**
议价成功与无优惠全程约 56 秒，未接通约 26 秒。进度由 `Date.now() - startedAt` 驱动，所以可以随时中断、刷新恢复、从记录页点回去继续看。

**记录会持久化。**
用 `localStorage` 存整条询价记录（含结果对象）。刷新后历史记录还在；没跑完的询价会按剩余时间继续跑完，不会永远卡在「正在沟通中」。

**绝不制造虚假交易状态。**
不拨真实电话，不出现订单号、支付成功、订房成功。结果卡固定注明「信息仅供参考，需以商家最终确认和实际预订为准」。

## 本地运行

```bash
# 直接双击 index.html，或者
python -m http.server 8000
# 然后访问 http://localhost:8000
```

页面外面那条控制条是演示辅助：

- **演示场景**：切换三种结局（默认议价成功）
- **跳到结果**：快进到结束，讲 Demo 时不用等一分钟
- **从头开始**：清空重来

## 关于示例截图

`samples/shot-price.jpg` 是一张 OTA 酒店列表页截图，用于「用示例截图试一下」这个入口。

识别出的字段是真实的：秋果酒店（北京三里屯太古里团结湖地铁站店）· 阳光双床房 · 1 晚 · 原价 ¥966 / 券后 ¥661 · 无早餐 · 有窗 · 18:00 前免费取消。

> 截图仅作为识别演示的输入，酒店与价格数据与任何真实预订无关。

## 技术说明

- 单文件 HTML，零依赖，无构建步骤
- 手机外壳 390 × 812，底部 tab（主页 / 记录），流程页自动隐藏 tab
- 所有商家、电话、通话内容、价格均为**演示数据**，不会发出任何网络请求
- 姓名和手机号只在本机内存里使用，不写入也不上传
